# FoolioBridge Protocol v1

The plugin (server) **polls** the site. The site never connects to the Minecraft server, so no ports need to be opened.

## Transport

* One URL on the site, e.g. `https://example.com/api/foolio`.
* Every call is `POST` with a JSON body, `Content-Type: application/json; charset=utf-8`.
* Redirects are not followed.

## Signatures

Shared secret `S` (16+ chars) is configured on both sides. Signature = lowercase hex `HMAC-SHA256(S, canonical)`.

| Direction | canonical string |
|-----------|------------------|
| request (plugin → site)  | `foolio-v1:req:{ts}:{nonce}:{body}` |
| response (site → plugin) | `foolio-v1:res:{ts}:{nonce}:{body}` |

* `ts` — unix time in seconds; `nonce` — 32 hex chars generated by the plugin per request; `body` — exact raw body bytes (UTF‑8).
* Request headers: `X-Foolio-Timestamp`, `X-Foolio-Nonce`, `X-Foolio-Signature`.
* Response headers: `X-Foolio-Timestamp`, `X-Foolio-Signature` (signed with the **request's** nonce).
* Both sides reject timestamps more than 300 s off. The site should reject a nonce it has already seen.
* The plugin trusts nothing in an unsigned or wrongly signed response.

Invalid signature → site answers `401` (unsigned). Errors after a valid signature are answered with `{"ok": false, "error": "..."}`.

## Request body

Common fields: `{"v": 1, "action": "...", "server": "<server-id>", "plugin": "<version>"}`

### `ping`
Reply: `{"ok": true, "pong": true}`

### `pending`
Reply:
```json
{
  "ok": true,
  "orders": [
    {
      "id": "1042",
      "player": "Steve",
      "uuid": "optional",
      "online_only": true,
      "title": "VIP на 30 дней",
      "message": "&aСпасибо за покупку!",
      "commands": ["lp user {player} parent addtemp vip 30d"],
      "vars": {"amount": "500"}
    }
  ]
}
```

* `id` (string ≤ 64), `player`, `commands` are required.
* `online_only` defaults to `true` (wait until the player joins). Set `false` for things that work offline (e.g. LuckPerms groups).
* Placeholders in commands: `{player}`, `{uuid}`, `{order}`, `{title}`, and every key from `vars` as `{key}`.
* The site keeps returning an order until its result is acknowledged. The plugin deduplicates by `id`, so returning it again is safe.

### `ack`
Request adds:
```json
"results": [
  {"id": "1042", "player": "Steve", "status": "delivered", "delivered_at": 1760000000000, "errors": []}
]
```
`status` is `delivered` or `failed`. `errors` lists warnings (unknown command, command not in allow-list, invalid nickname, duplicate).

Reply: `{"ok": true, "accepted": ["1042"]}` — ids the site saved. Missing `accepted` = all accepted. Unaccepted results are re-sent on the next poll.

## Delivery guarantees

* The plugin writes the order's result to disk **before** running commands → a crash can't deliver twice.
* Results are re-sent until the site confirms them.
* Finished order ids are remembered for 30 days, so a site bug that re-sends an old order won't re-deliver it.
